Polygon Publishes Heimdall v0.14.0 After Purley Goes Live

Polygon has made Heimdall v0.14.0 public after Purley activated on mainnet and Amoy, adding new checks for validator votes, bridge events, staking updates and checkpoints.

Onchain Report NewsroomNov 21, 2026 · 10:44 UTC#0738c32 min read

Polygon has published Heimdall v0.14.0, the public release of its Purley network upgrade, after the change activated on mainnet and the Amoy testnet. Heimdall coordinates validators and checkpoints for Polygon’s proof-of-stake network. Polygon’s release announcement says the upgrade is active on both networks.

Purley activated on mainnet at Heimdall block 58,280,000 at 01:39:38 UTC on November 20. On Amoy, it activated at block 52,108,000 at 15:41 UTC on November 12. A hard fork is a network upgrade that takes effect at a set block height.

What Heimdall v0.14.0 changes

The release changes how Heimdall handles validator votes, bridge events, staking updates and checkpoints. A vote extension is extra data attached to a validator’s vote. Under Purley, that data is carried as signed and authenticated information in every block that includes it. Bridge events must also be confirmed before the network acts on them.

Stake updates are accepted only when they use the validator’s next nonce, a number that helps keep its transactions in order. The release also keeps an expired checkpoint buffer until an approved checkpoint replaces it. Cancelled governance proposals with no destination set are no longer charged, according to Polygon.

What node operators need to know

Polygon says nodes must run the compatible Purley build or a later version. Its Heimdall v0.14.0 release notes describe the public version as functionally identical to the private build used for activation.

The upgrade is a binary update, Polygon says. It requires no configuration changes, state migration or resynchronisation, and no Bor change. Bor is Polygon’s block-production client. The release notes also list changes outside the activation-height rules: Heimdall rejects staking messages with no amount during basic validation, and packaged configuration templates leave the external-address field empty.

The release makes the Purley source code public after both networks passed their activation heights. Polygon lists no transaction-speed or fee changes in the release notes; the documented updates concern validator coordination, bridge events, staking and checkpoints.
