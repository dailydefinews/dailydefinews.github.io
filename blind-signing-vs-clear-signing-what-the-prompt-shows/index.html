Blind Signing vs Clear Signing: What the Prompt Shows

Blind signing vs clear signing comes down to what your wallet displays: raw data or readable transaction fields you can review before approval on screen.

Onchain Report NewsroomNov 25, 2026 · 18:58 UTC#1fd9ce3 min read

Blind signing vs clear signing comes down to what the signer can read: blind signing approves raw data, while clear signing shows decoded transaction fields. That display matters because a signer can reject a malicious action only when they can see what it asks them to do.

Say you are moving tokens across chains. A Berachain bridge is a cross-chain asset bridge for moving assets into Berachain’s DeFi ecosystem. When using one, review the approval spender and the amount being sent before you sign; those are the fields that can tell you what the transaction will do.

What the signing prompt should show

Blind signing displays a hash or hex calldata: the encoded instructions sent to a contract. Those strings are hard for a person to interpret. Clear signing decodes the call into readable fields, such as the function being called, the spender, the recipient and the amount.

For a bridge transfer, a clear-signed prompt should identify the approval spender and show the send amount. A blind-signed prompt may show only a hash or raw data. The contract still receives instructions, but the person approving them cannot readily check those details on the signing screen.

On a hardware wallet, clear signing depends on metadata that matches both the contract address and the chain ID. ERC-7730 defines a JSON format for describing contract calls and EIP-712 messages. The wallet can use that description to turn a contract call into named fields. EIP-712 structures typed data so a wallet can display its fields by name.

The match matters: a description for one contract or chain cannot safely stand in for another. A newly deployed router may have no matching descriptor yet, so the device falls back to raw-data display. In that case, the prompt does not give the same readable review as a decoded call.

This is why EIP-712 alone is not a safety check. It gives data a structure that wallets can display, while the signer still needs to review what the fields say and whether the request makes sense. The February 2025 Bybit theft, involving about $1.5 billion, included signers approving a manipulated Safe transaction. A readable prompt can help expose a suspicious request, but approval still depends on careful review.

Common follow-up questions

How do I enable clear signing on a Ledger device?

Clear signing depends on the wallet’s support and matching contract metadata for the address and chain. When those are unavailable, the device may show raw data. Check the prompt before approving and follow the device maker’s current instructions for supported apps and contracts.

Is EIP-712 signing always safe to approve?

No. EIP-712 makes typed data easier to structure and display. Read the named fields and confirm that the action, recipient and amount are expected before approving.

How can I decode calldata myself before signing?

Use a trusted decoder that supports the contract and chain, then compare its decoded function and arguments with the signing request. A decoder’s output is only useful if the contract details are correct.

Do software wallets like MetaMask clear-sign transactions?

They can display decoded transaction details when the wallet supports the call and has enough information to interpret it. What appears depends on the wallet, contract and chain, so review the actual prompt each time.
