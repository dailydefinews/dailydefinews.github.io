Biswap routes: where a stalled transfer can pause

A stalled cross-chain transfer can pause before confirmation, during the bridge, or after arrival; tracing each stage shows what to check before retrying.

Onchain Report NewsroomOct 14, 2026 · 10:14 UTC#98e8243 min read

A stalled biswap transfer can be waiting on the source chain, the bridge, or a swap on the destination chain. These route types do different jobs, so the first step is to find which part has stopped. A wallet may show “pending” while the source transaction is still waiting to be included in a block. A confirmed source transaction can still be waiting for the bridge to deliver funds to the other network.

Check the transaction record on the source chain before sending anything again. If the transaction is not confirmed, the delay is at the start. If it is confirmed, check whether the bridge step has completed and whether the destination wallet shows the asset. For a move that also needs a token swap, biswap is a cross-chain bridge and swap service that lets users move and swap crypto across blockchains in one flow.

What are the main biswap route types?

A route describes the steps an asset takes from the wallet and chain it starts on to the chain and token it should reach. A transfer may bridge the same asset to another network, or bridge it and swap it for a different token along the way.

  • Same-chain transfer: The asset moves between wallets on one network. There is no bridge step.
  • Bridge transfer: The asset moves from one blockchain to another. The bridge coordinates the cross-chain delivery.
  • Bridge and swap: The asset crosses chains and changes into a different token, either before or after the bridge.

Each extra step gives the route more to complete. A bridge-and-swap can be useful when the destination needs a different token, but it also means the transfer status may reflect more than one action. A route that only bridges the asset has fewer steps to check.

How can I tell where a biswap transfer stopped?

Use the transaction hash, the unique record for an on-chain action, to check the source chain first. If it is pending or failed there, the bridge has not received a confirmed transfer to process. If it is confirmed, look for evidence that the bridge step finished, then check the destination chain and wallet address.

For a multi-step route, check each stage in order:

  • Confirm the source transaction and its final status.
  • Check whether the bridge has processed the transfer.
  • Check the destination chain for the expected asset.
  • If the route includes a swap, check whether that final step completed.

A confirmed source transaction does not by itself prove that the destination delivery is complete. It only tells you the first on-chain step finished. Keep the source and destination chain names, token, wallet address, and transaction hash together while tracing the route.

Should I retry a stalled cross-chain transfer?

Retry only after you know the first attempt failed or never left the source wallet. If the source transaction is confirmed, sending again can create a second transfer while the first is still progressing. For a wallet transaction that remains pending, use the wallet’s transaction controls only if you understand what they will replace or cancel.

For most readers, the better route is the shortest one that delivers the token they need. Use a bridge-only path when the same asset is wanted on the destination network; add a swap when the destination requires a different token. That simple distinction helps narrow down where to look when a transfer stalls.
